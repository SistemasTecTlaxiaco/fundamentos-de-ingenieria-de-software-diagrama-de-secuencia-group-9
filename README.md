# Práctica 10 · Modelo de dominio y diagramas de secuencia

Fundamentos de Ingeniería de Software (SCC-1007) · Unidad 4 · Sprint 4 · Open Hub Tec

Integren el negocio (Unidad 2) y los requisitos (Unidad 3) en una sola representación técnica: modelo de dominio, diagramas de secuencia y modelo de arquitectura, validados con la organización.

## Qué entregan

| Archivo | Qué lleva |
|---|---|
| `entrega/practica-10.md` **o** `entrega/practica-10.pdf` | La plantilla llena, con sus 10 secciones (una por criterio de la rúbrica). Es su documento integrador. |
| Imágenes (`entrega/img/` o `docs/analisis/`) | Al menos 4: modelo de dominio, 2 secuencias y arquitectura |
| `modelo/OpenHub-Equipo.qea` | El mismo proyecto de Architect de la Práctica 9, con los diagramas nuevos y el diagrama de clases actualizado |

Si entregan en PDF, exporten la misma plantilla y **no cambien los títulos de las secciones**.

## Cómo se trabaja

1. `git pull` y creen una rama: `git switch -c practica-10-secuencia`
2. Hagan sus cambios, `git add .`, `git commit -m "..."`, `git push -u origin practica-10-secuencia`
3. Abran un **pull request** hacia `main` y llenen la autoevaluación de la plantilla.
4. Un robot revisa la entrega y deja un comentario con lo que falta. **No califica**: solo confirma que la información que pide la rúbrica está. Mientras falte algo, el pull request no se puede fusionar.
5. Corrijan en la misma rama; la revisión se repite sola con cada `push`.
6. Cuando el robot marque todo completo, otro integrante revisa, aprueba y fusiona.

La calificación la pone el Product Owner con la rúbrica de 30 puntos.

## El repositorio es público

La minuta de la presentación va con el **cargo** de cada persona, no con su nombre completo ni datos de contacto. No suban firmas escaneadas: el original firmado se entrega al docente. El robot avisa si encuentra teléfonos, correos o CURP.
